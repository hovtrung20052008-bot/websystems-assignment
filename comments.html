1. Website structure

The website has four pages connected by the same navigation menu. Each menu link opens a separate HTML page, while websystems.css provides shared styles such as the navigation and footer. All shared and page-specific styles are kept in this single stylesheet.

  • Home introduces me and my hobbies.
  • My Past describes my early experiences with technology and people who inspired me.
  • My Future describes my goals and ideas.
  • Comments explains the website design.

When a page opens, the browser reads its HTML structure, loads the shared stylesheet, and loads images from the local image folder. The navigation uses relative links, so choosing a page opens another HTML document in this assignment. The Home page also links to UTS in a new tab and includes image-credit links. The site uses HTML and CSS rather than JavaScript: the content is static, and the navigation and CSS hover/focus effects provide its interactions.

2. Detailed contents of the three main pages

The Home, My Past, and My Future pages share the same four navigation links and footer design. The footer email is plain text on Home and a mail link on My Past and My Future. Each page has a main heading and groups its content into sections. The lists below describe the visible content and page elements in those three HTML files.

How the page markup works

Each file starts with a doctype and an English-language HTML document. Its head sets the character encoding and responsive viewport, links websystems.css, and supplies the browser-tab title. The body contains the site header, navigation, main content, and footer in that order. The navigation links connect the four separate HTML files; the current-page class is placed on the link for the page currently being viewed.

  • Home (index.html): the main content starts with the page heading and an intro-layout container. Its introduction section and campus-image section are arranged together, followed by a hobbies section. Each hobby uses a list and image grouped in a hobby-list container. The image alt attributes provide text alternatives. Its footer displays the email address as plain text.
  • My Past (past.html): the main element uses page-content past-content classes to identify and lay out the page. Three story sections use IDs to target their headings and content. A fourth section contains a semantic table: its caption names the table, the header row labels each column, and the body rows pair each person with a field and explanation.
  • My Future (future.html): the main element groups the future-goal sections and images. The dream section contains a nested subheading for the proposed extension. The concept image has alternative text and a descriptive paragraph. The later section contains future goals and a gallery made from figure, img, and figcaption elements, which keep each image paired with its caption.

3. How the CSS decorates the pages

websystems.css contains rules made from selectors and declarations. A selector chooses matching HTML elements; declarations set their appearance or layout. Element selectors such as body match HTML tags, class selectors such as .future-gallery match a class, ID selectors such as #Dream match a unique ID, and pseudo-classes such as :hover apply during an interaction. More specific selectors can style a child differently from its parent. The shared rules below apply across pages when their selectors match; page-specific rules only affect elements with the corresponding ID or class.

How the CSS layout and cascade work

  • Spacing and the box model: margin creates space outside an element; padding creates space between its content and border. Borders, backgrounds, text color, font size, and line height provide the visual treatment. For example, the white section panels use padding to keep text away from their edges and margins to separate them from neighboring content.
  • Selector matching and the cascade: a rule only affects elements matched by its selector. IDs target specific sections, while reusable classes can group related elements. When selectors of equal specificity set the same property, a later declaration wins. In this stylesheet, later rules change the final margins of #Dream and #MyFuture; the table explains that override where it applies.
  • Layout systems: Flexbox lays out direct children of a flex container along a row or column and distributes available space. This is used for the Home introduction and hobby rows, and wraps the My Future gallery figures onto new rows when needed. The My Past content and most other sections use normal document flow, which stacks block elements vertically. A flex declaration has no flex-item effect unless the element's parent is a flex container.
  • Images and page width: object-fit: cover fills a fixed frame by cropping excess image area; contain keeps the whole image visible. The future gallery's wrapping Flexbox lets its figures share a row when there is room and move to another row when there is not, without a media query. The stylesheet has no explicit breakpoint rules, so other layouts may need additional testing and responsive adjustments on narrow screens.

4. Visual design

  • Shared identity: the light blue-grey page background (#f5f7fb) and dark blue-grey text (#263248) provide a consistent base. White panels, thin blue-grey borders, and rounded corners separate content without changing the shared page structure.
  • Color accents and hierarchy: indigo (#3730a3 and #6366f1) highlights headings, current navigation, focus states, and the footer border. Font size, weight, color, and spacing distinguish page titles, section headings, body text, captions, and table labels.
  • Page-specific layouts: Home puts introduction text beside a campus image and places hobby images beside lists. My Past uses vertically flowing story panels and a structured comparison table. My Future emphasizes its concept illustration and arranges the two gallery images in a Flexbox row that can wrap onto another row.
  • Consistent finishing: the sticky navigation keeps page links available while scrolling. The dark footer and indigo top border close each page with a repeated visual element. Hover and focus states provide feedback when links are pointed at or reached by keyboard.

The stylesheet has no media queries. The navigation and future gallery can wrap as space changes, but other layouts do not have separate breakpoint rules and should be checked on narrow screens.

5. Accessibility

  • Document setup: each page declares English as its document language, UTF-8 text encoding, and a viewport setting so browsers can scale the page to the device width.
  • Structure: header, navigation, main, and footer elements identify the main page landmarks. Headings and sections divide information into a hierarchy, and the Comments page's section headings are connected to their sections with aria-labelledby.
  • Images: content images on Home and My Future include descriptive alt text, so their subjects can be understood if the image is unavailable or when a screen reader is used. My Past and Comments do not use content images.
  • Links and keyboard use: anchors provide native keyboard navigation. The shared navigation has visible hover and keyboard-focus styling; links in the Comments explanations also receive a visible focus outline. The current-page class visually highlights the active link.
  • Tables: both tables use a caption or header row to explain their content, with header cells separating column labels from data. The Comments table also uses scope="col" to associate its column headings with their columns.

If CSS is turned off, the text, headings, lists, tables, and links remain in the document and the navigation still works. The colours, spacing, borders, and page layouts provided by CSS are lost.
